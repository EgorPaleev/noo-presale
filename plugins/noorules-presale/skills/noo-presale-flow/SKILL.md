# Пайплайн NooRules

Сначала [проверь подключение текущего проекта](../noo-presale-task/references/project-context.md#подключение-проекта). Выполняй этот навык NooRules Presale в подключённом проекте.

Если просят только посоветовать или сохранить пайплайн, используй [правила выбора и сохранения](references/composition.md) и заверши работу рекомендацией или сохранённым определением.

Для `presale-full` используй [единый регламент](../../assets/knowledge/base/presale/workflows/presale-playbook.md) и [сборку пресейла](references/composition.md#пресейл). Новый полный запуск проходит через [план и вопросы](references/approval.md), включая прямой вызов этого навыка. После запуска выполняй все готовые этапы с проверками в том же ходе.

1. Если предоставлен ID запуска, прочитай [состояние](references/state.md). Уточни статус или продолжи со следующего готового этапа согласно запросу. Для нового запуска [подбери или собери пайплайн](references/composition.md) и используй [порядок согласования](references/approval.md). Если `noo-presale-task` уже передал одобренный план, продолжи по нему.
2. Преврати одобренный план в этапы. Для именованного пайплайна возьми контракт из выбранного проектного или [встроенного определения](../../assets/knowledge/flows.json). Маршруты используй для подбора материалов. Для каждого этапа зафиксируй цель, входы, выход, зависимости, модель и критерий завершения. Назначь файлы для плана и результатов по [правилам размещения](references/state.md#где-сохранять-файлы). Если у маршрута нет отдельного исполнителя, используй его материалы и `noo-presale-task` как исполнителя этапа. Проверь, что у каждого входа есть источник, все зависимости указывают на существующие этапы и в графе нет циклов. Запиши контракты и ссылку на план в `run.json`. При изменении принятого входа возобнови текущий ID по правилам состояния.
3. Сообщи ID в промежуточном сообщении и сразу начни готовый этап. Вызови инструменты делегирования для назначенных субагентов с моделями из плана. Выполняй свои готовые этапы в ходе их работы. При продолжении восстанови назначения из состояния. Если инструмент, модель или слот недоступны, сообщи фактическую причину и примени резерв из плана без повторного согласования.
4. Показывай ход работы в чате. На старте каждого этапа назови этап, исполнителя и ожидаемый артефакт. После завершения покажи результат и выполненную проверку. Для демо примени [приёмку прототипа](../noo-presale-prototype/references/presale-acceptance.md) перед закрытием этапа. При блокере скажи, чего не хватает и что выполняется дальше. Можно объединить одновременные события в одном сообщении с отдельной строкой на этап. Записывай эти переходы в состояние. Передавай зависимым этапам принятые результаты. Запускай следующий готовый этап сразу после появления входов. Пока есть работа в согласованном объёме, продолжай выполнять её после промежуточных сообщений.
5. Сверь все пункты согласованного плана и согласованность артефактов. Проверь, что важные утверждения опираются на входы, а допущения помечены. Убери шаблонные фразы и дубли. Передай результаты и инструкции для повторного использования, ID запуска и фактические проверки. В состоянии укажи модели и применённые материалы. Для заблокированных этапов назови причины. Когда все запрошенные этапы приняты и файлы выданы, [закрой запуск и очисти служебные файлы](references/state.md#завершение-и-очистка).
