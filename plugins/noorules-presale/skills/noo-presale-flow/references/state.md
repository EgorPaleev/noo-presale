# Состояние запуска

Используй один активный исполнитель записи. Координатор сохраняет согласованный план, исходный запрос, входы, отпечатки и состояния этапов. Субагенты записывают назначенные артефакты в свои пути. Координатор обновляет общий `run.json`.

## Где сохранять файлы

- Перед запуском выполни `python3 <навык>/scripts/run_state.py <id> --prepare` из корня текущего проекта. ID состоит из строчных латинских букв, цифр и дефисов. Служебные материалы одного запуска держи в `.noorules/runs/<id>/`. Скрипт создаёт локальный игнор внутри `.noorules/runs/`. Для Git проверь исключение до записи состояния. Если исключение недоступно, храни состояние в текущем чате и сообщи об ограничении восстановления по ID.
- Для выдачи используй `presales/<id>/` или папку, которую указал пользователь внутри проекта и вне служебного каталога. Публикуй туда только запрошенные документы, демо и отчёты. План исполнения, исходные снимки, рабочие заметки и данные для расчёта оставляй в служебном каталоге. Стадии пишут рабочие файлы в разные пути.
- Сохраняй относительные пути в [`run.json`](../../../assets/knowledge/flow-run.schema.json). Запиши `deliveryPath` и `delivered` со списком реально выданных файлов. Для явно запрошенного результата, который уже выдавался в этом запуске, обновляй тот же файл после проверки. Перед изменением убедись, что он принадлежит этому запуску и его не менял пользователь.
- Для старого ID с результатами в корне используй сохранённые ссылки для чтения. Для новых рабочих файлов и выдачи примени текущие правила. Очистка удаляет только служебный каталог этого ID.

## Статусы и продолжение

- Сохрани версию плагина, план и его отпечаток. В каждом этапе укажи `inputs`, при необходимости `optionalInputs`, `dependsOn`, `output`, планового исполнителя в `executor`, модель и критерий готовности. Файлы входов идут из принятых результатов предшественников или из `externalInputs`. Необязательный вход с отсутствующим файлом не блокирует этап. Зависимость добавляй, когда результат запланированного этапа требуется дождаться.
- Ставь `pending`, `running`, `waiting`, `completed` или `stale`. На переходах этапа сохраняй `activity.message`, фактического исполнителя в `activity.executor` и время в ISO 8601. При `waiting` укажи причину. Если доступен полезный черновик, приложи его, укажи ограничения и сохрани реально использованные входы. Помечай `completed` только после проверки артефакта и записи `usedInputs` и `result`. Если просили финальную цену и она ожидает ставки, сохрани черновики, а итоговую сверку оставь в ожидании, чтобы запуск можно было продолжить.
- Сохраняй отпечаток файла через SHA-256 или `git hash-object --no-filters -- <путь>`. Подкрепляющие файлы, например XLSX и структурированный расчёт, указывай в `result.dependencies`. При продолжении сверь текущие файлы и версии контрактов. Для статуса по ID используй `python3 <навык>/scripts/run_state.py <id>`, а для недоступного или закрытого ID укажи известную папку выдачи.
- Храни исходные данные отдельно от изменяемых параметров. Роль `pricing` используется только в смете. Когда пользователь обновляет ставки или НДС открытого запуска, сохрани параметры в отдельном файле и выполни `python3 <навык>/scripts/run_state.py <id> --set-input pricing <относительный-путь>`. Для любого другого принятого внешнего входа аналогично передай его роль. Скрипт принимает отпечаток нового файла и помечает затронутый этап и его потомков. Для неизменившегося файла ничего не перестраивай.
- При изменённом рабочем артефакте пометь устаревшим его этап и результаты, использующие его прямо или транзитивно. Переиспользуй независимые результаты с подходящими отпечатками. Пересобирай устаревшие этапы в порядке зависимостей из того же ID. У задачи со ставкой это смета, КП и сверка. Демо и разбор сохраняются.
- Если пользователь расширяет уже открытый запуск, покажи изменения пайплайна на согласование. После запуска добавь согласованные этапы и зависимости в сохранённый граф. Проверь пригодность существующих результатов и пересобери только те этапы, на которые влияют новые требования или зависимости.
- Укажи реально применённые материалы и их вклад в `appliedMaterials`. Фактически использованную модель указывай по данным среды.

## Завершение и очистка

После принятия всех запрошенных этапов перенеси выдачу в `deliveryPath`, проверь файлы, запиши `delivered` и выполни `python3 <навык>/scripts/run_state.py <id> --close`. Скрипт проверяет статусы и наличие результатов в папке выдачи, затем удаляет служебный каталог запуска. Выданные файлы сохраняются. При ожидании данных для принятого результата оставь запуск открытым. Черновик, если пользователь просил именно его, может завершить запуск после проверки и выдачи. Чтобы изменить уже закрытую задачу, начни новый запуск с выданных файлов или актуальных исходников.
