# Работа субагентов

Для полного пресейла проверь, есть ли доступные инструменты делегирования и список моделей. Предложи назначение в первичном плане. Оставь объединение итогов координатору. Исследование клиента можно делегировать параллельно с разбором. После плана смету и демо можно поручить разным исполнителям. Для коммерческой сверки можно назначить отдельного проверяющего, когда нужен независимый взгляд. Число одновременных исполнителей определяй по доступным слотам и зависимостям.

Координатор передаёт каждому субагенту цель одного готового этапа, выдержку из одобренного плана, входные файлы, ожидаемый результат, критерий проверки и выделенный [путь для записи](state.md#где-сохранять-файлы). Рабочие файлы остаются в каталоге запуска. В поручении укажи, что этап уже согласован и субагент выполняет его сам. Общее состояние запуска обновляет координатор.

Передавай только нужные этапу пути, ограничения и подтверждённые результаты. Укажи уже известный маршрут, если он подходит. Субагент самостоятельно проверяет его и выбирает материалы. Объединяй тесно связанные работы с общим входом в одном этапе, если разделение дублирует чтение и проверки.

Для `presale-demo` передай явный путь к `noo-presale-prototype/SKILL.md` из активной сборки и референсы из поручения пользователя. В критерий завершения включи [визуальную приёмку](../../noo-presale-prototype/references/presale-acceptance.md). При повторном открытии этапа по замечанию пользователя используй предыдущий прототип как вход для доработки. Прими обновлённый артефакт после проверки.

При запуске каждого субагента установи модель и глубину рассуждения этого этапа параметрами инструмента, если среда их поддерживает. Передача имени модели в тексте поручения не меняет модель. Если нужная модель или параметры недоступны, используй согласованный резервный вариант или настройки родительской сессии и укажи причину. Название фактической модели и глубину рассуждения записывай только при подтверждении средой.

Субагент самостоятельно изучает действующие инструкции проекта, подбирает маршрут по [карте задач](../../../assets/knowledge/task-index.md) и вызывает [noo-presale-rules](../../noo-presale-rules/SKILL.md) для своей подзадачи. Затем он выбирает применимый навык-исполнитель и дополнительные инструкции из найденных материалов. Если механизма вызова нет, он открывает соответствующий `SKILL.md` и работает по нему. Использует входы на чтение и пишет только по выделенным путям. Если выбранный метод требует изменения контракта этапа, передаёт решение координатору.

В ответе координатору субагент указывает путь результата, проверки, допущения и блокеры. Для каждого заявленного навыка или правила кратко укажи, к какому решению, изменению или проверке он привёл. Координатор сохраняет в `appliedMaterials` этапа фактически применённые материалы и их вклад. При отсутствии проверки или обоснования, которое влияет на приёмку, координатор уточняет результат до запуска зависимого этапа. Если применимых правил нет, достаточно пустого списка правил с коротким объяснением. При расхождениях координатор сверяет источники и фиксирует решение в итоговых артефактах.
